## 4. 自动诊断与修复循环

以前，Executor可以修复部分运行错误，但生成文件之后若Supervisor核验失败，流程会直接终止，不能继续把错误交回Engineer。

现在，GUI与CLI共用`run_execution_cycle`。执行错误与可修复的产物错误进入同一个受限循环；修复后重新运行和核验，通过后才交付给Manager。Supervisor独立调用时仍按原有方式阻断失败，只有明确处于受控循环时才允许修复。

- 默认最多5次执行尝试，包含第一次；额外修复请求最多4次。执行错误与核验错误共用预算，不各自另起一轮。
- 每次修复带上原需求、有序修改、已确认任务、数据事实和上一版完整代码；后续又补入同一份任务约定。
- 同一任务重试复用原输出目录，并累计本循环实际生成的文件，避免只修CSV后漏掉原图或此前失败文件。
- 缺少必要数据、跨任务产物、用户终止、预算耗尽或Engineer未返回可执行代码时停止；不会生成成功报告。
- 删除必需统计字段、留下旧的损坏CSV或改用无法识别的表格，不能被当作修复成功。
- 每次核验记录`artifact_validation`追溯事件，保留尝试次数、错误、提示和文件清单。

以`could not convert string to float: 'N/A'`为例：本次新增的是把错误交给Engineer修复任务输出格式的回路，核心读取器没有改变。确实不可计算的可选面积可以省略面积列并说明原因；不能把未知面积填成0，也不能保证所有`N/A`错误都自动修好。

## 5. 用户目标与输入沿途保留

新增`tools/task_contract.py`，把原需求、有序修订、辅助任务类型、目标对象、锁定输入和输出要求组成同一份任务约定。Manager、Scientist、Engineer、自动修复和最终交付使用这份记录。

用户明确选择的文件优先；需求中能定位的文件或目录也可锁定。GUI与CLI在已有锁定输入时不再重新匹配其他影像。确认指令不会覆盖输入选择或替换原需求。

这一机制用于减少目标漂移，例如避免把“找出建筑变化”无声改成“只做亮度差分后宣称完成建筑识别”。目前它主要依靠常见中文规则辅助分流，仍需模型规划和必要的需求澄清，不能保证理解任意复杂、多目标问题。

## 6. 已知数据条件检查

| 用户需求或条件 | 当前处理 |
|---|---|
| 只给数据，没有明确目标 | 先推荐可以做的分析；空目标的自动托管不直接决定任务 |
| 选中文件不存在或不可读 | 指出问题并阻断进入Scientist模型调用 |
| 明确只选一期，却要求前后变化 | 提示需要同一区域的第二期影像并阻断 |
| 波段已明确为普通RGB，却要求可靠地表温度 | 指出缺少测温信息并阻断 |
| 有可能的测温数据，但单位或校正不明 | 保留待复核，要求核对产品类型、单位与校正条件 |
| 影像没有真实地理定位 | 说明只能描述图内位置，不能可靠换算实际面积 |
| RGB影像要求识别建筑 | 不误判为天然无法识别；未接入经验证的专业模型时保持候选状态 |
| 云遮挡区域补全 | 说明补全属于推算，不能当作真实地表的直接观测 |

检查通过仅代表没有命中这些已知阻断条件，不代表方法合适或遥感精度合格。当前`semantic_verified`仍为false，没有新增完整的物理反演审查或任意数据适用性证明。

## 7. 文件选择、预览与结果交付

新增`gui/data_files.py`，可以选择本地已有TIFF、添加TIFF和查看缩略预览。每次上传1～8幅，整个请求上限128MB，保存到新的`data/uploads/<随机目录>/`，不覆盖原数据；校验失败只清理本批新文件。分析运行时拒绝新增上传。

缩略图最大边长512像素，采用显示拉伸，仅供选择输入，不用于定量计算，也不能证明真实颜色。

新增`tools/result_delivery.py`，依据当前任务约定、核验事实和实际文件构建结果卡片，包含：

- 用户想了解什么、初步结论、结果图和统计表中的记录。
- 文件与统计是否已检查、是否经过独立准确性验证。
- 需要留意的事项、下一步建议与本次结果下载入口。
- 可展开的专业报告、任务记录和机器检查依据。

默认结论不直接采纳模型自称的“可信度99%”。识别、变化、去云和温度目前保持候选或待验证；没有独立答案对照时，明确说明准确性尚未验证。失败任务不展示成功产物，没有图片时不冒称已完成制图。CLI也使用同一份通俗结果说明。

结果下载限制到本次核验清单与任务目录内的实际文件，并限制类型；不会把旧任务结果或真实配置作为本次下载。上述边界检查和提示词约束不等于操作系统级安全沙箱。

## 8. 当前最终界面

- 桌面右侧：分析管线、执行进度、监督、追溯和导出按钮，独立于分析过程的折叠状态。
- 对话区上方：目录文件扫描，默认收起，可以用鼠标或键盘展开、收起和刷新；刷新保留展开状态。
- 对话框内：完整分析消息、代码、相关数据记录和本次对话，放在可展开的“查看分析过程与数据”里。
- 分析结束：直接显示图和通俗说明；需要方法、参数与核验依据时，在结果下方展开专业详情。
- 同一轮询快照不会重建卡片、重置用户已展开的详情；刷新恢复当前结果，新建会话清除旧卡片和过程。
- 长回复保留全文和原按钮事件；折叠区域收到的长代码也能展开。完成步骤显示实际勾号，避免显示HTML实体文本。
- 窄屏保留顶部扫描、对话内过程和新建入口；沿用原布局在宽度不超过1100像素时隐藏右侧管线的规则。
