## 结论

18次离线编排均正确绑定输入、选择工具、执行并完成独立评价，其中新4幅各4种说法共16次，旧2幅各1次。相同输入换说法，预测像元SHA256完全一致。**这是工程流程与规则选路通过，不能称为18次识别质量合格。**

新场景表现差异明显，固定方法无法保证把所有水体找全：

| 案例 | 标出的有多少是对的（Precision） | 真实水体找回多少（Recall） | F1 | 漏掉的参考水体 |
|---|---:|---:|---:|---:|
| water_03 | 91.01% | 89.98% | 90.49% | 10.02% |
| water_04 | 95.57% | 99.93% | 97.70% | 0.07% |
| water_05 | 91.86% | 46.38% | 61.64% | 53.62% |
| water_06 | 94.56% | 62.19% | 75.03% | 37.81% |

四例等权宏平均F1为81.22%；合并全部像元的微平均F1为87.91%。大水面案例对后者影响更大，因此不能只报这个较高的分数。全部预测覆盖率100%，没有通过删除未确认像元提高成绩。没有统一“80分即合格”标准，是否满足应用要求仍需任务标准与更多独立验证。

water_05有连片水面漏检，不只是边缘小误差。05、06漏检区域的MNDWI中位数分别约为-0.118、-0.260，均落在固定零阈值外。这说明现有方法在这些区域失效；仅凭这些统计不能确定浑浊、阴影或传感器处理等具体成因。没有据此调整阈值或挑选更好看的样本。

## 数据来源与冻结边界

来源为作者发布的[ESWD v2影像和人工标签](https://zenodo.org/records/5205674)，输入波段说明参照作者[WatNet仓库](https://github.com/xinluo2018/WatNet)。本批比较对象是人工标签，未下载、运行或对比WatNet模型预测。许可备注沿用已有下载清单，本地研究使用；原始影像、标签和产物不进入Git。

在读取任何新影像、标签和预测前，按已有ZIP目录的文件名、采集前缀和大小冻结选样规则，排除原2幅采集，剩余8个采集按排序取索引0、2、5、7。规则、固定算法版本和4种话术保存在[冻结协议](../benchmarks/protocols/water_20261025.json)。协议SHA256：`0e05aa4f9226d8a35bcb34f64f40113ee7c88bc27b659743cd7164f716843b4b`。

分段下载约31MB，逐段校验Content-Range、长度与缓存哈希，原ZIP成员校验CRC。新输入只补波段描述，不改变像元、空间网格、比例系数与偏移；原始标签0/1保持不变，0为有效背景，不重采样。输入、元数据和参考答案SHA256写入 `benchmarks/cases.json`，与已有9例合并为13例，其中6例接入水体评分。

## 从什么改成什么

| 文件 | 之前 → 本批 |
|---|---|
| `tools/task_contract.py` | 仅“水体”稳定识别 → 将水面、水域、湖泊、河流归一到水体；保留原文，路径本身不提供分析目标 |
| `tools/water_workflow.py` | 部分额外需求可能误走面积提取 → 水深、水质、宽度、矢量、明确其他方法等继续原规划；算法词出现在影像路径中不等于用户指定方法 |
| `benchmarks/metrics.py` | 只计算数值 → 从混淆矩阵给出多数漏检、多数误报、未确认区域的事实提示，不新增任意F1合格线 |
| `tools/water_evaluation.py` | 逐幅给面积和指标 → 同时附加质量标记与通俗提示；无独立答案不推断语义精度 |
| `tools/result_delivery.py` | 默认只说逐幅生成 → 明显漏检/误报直接写入结论与下一步；缺产物仍失败，不能被场景提示覆盖 |
| `benchmarks/runner.py`、`gui/templates/benchmarks.html` | 固定两例的旧说明 → 新旧场景标签、6个水体案例、同一质量提示及当前调用范围 |
| `benchmarks/cases.json`、`benchmarks/protocols/` | 9例材料、2例评分 → 13例材料、6例评分与本批冻结协议 |
| `tests/test_water_phrases.py`、`tests/test_water_evaluation.py` | 无这些覆盖 → 同义词、额外要求、路径歧义、质量提示和缺产物失败回归 |

本批未改角色提示词文件、DeepSeek模型/API配置、依赖环境或像元算法。FIX-009已有的角色和提示词改动继续保留。

新增兼容字段 `quality_flags` 为字符串列表，默认视为空，值为 `majority_water_unconfirmed`、`majority_candidates_wrong`、`incomplete_prediction`。生产者是独立指标解释器，消费方是验收报告和逐幅交付；既有GUI展示结论与findings，专业JSON可查标记。`result_audit.scenes`、`result_delivery.scene_results`沿原Session字典保存，无新状态机枚举、消息类型、API路由或全局模式切换。

“漏掉多数”由FN>TP触发，“候选多数错误”由实际候选误报FP（扣除缺测背景惩罚）>TP触发。未触发这些强提示不表示合格。没有答案时只能提示未确认区域，不能知道漏掉了多少真实水体。质量差不进入修改CSV的工程修复循环；多算法选择和科学效果自动重规划尚未实现。
