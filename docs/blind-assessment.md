# FIX-011：普通分析不读答案，交卷后独立评分

2026-10-26，本批继续同一水体验收任务分支 `codex/validated-water-benchmark`，保留FIX-008～010未提交改动。当前为本地修改，未提交、未推送、未创建PR，审批与合并未执行；远端基线未重新同步。没有修改DeepSeek配置、依赖环境或固定水体算法。

## 现在的处理流程

```text
影像＋一句话需求 → 既有Agent处理 → 无答案产物核验 → 给普通用户的结果
                                                          ↓ 结束后明确交卷
                                    复制本次产物＋清单 → 封存答卷与收据
                                                          ↓ 单向传递
人工参考答案 ──────────────────────────────→ 独立评分报告
```

普通GUI、CLI共用的Supervisor不再读取参考答案或评分清单。它继续检查实际文件、类别编号、像元数、面积、占比、输入网格及工具版本；逐幅图与通俗结果保持原布局。无效像元会提示未确认，但不能推断漏掉多少真实水体。正常结果不再出现基于人工答案才能知道的精确率、找回率和漏检面积。

旧版会在Supervisor阶段对匹配案例评分，再让Manager引用分数。现在读取答案只发生在开发者外部测评入口。常见的无依据精度数字会被报告检查拦截并改用产物事实；该规则不是完整的语义判别器，不能保证捕获所有文字错误。实际方法与图示形式写入核验事实，减少将短波红外误写为近红外、将左右对照误写为叠加图的问题。

## 答卷和报告如何保存

`results/task_.../submission/`是复制后的答卷，包含 `submission.json` 与 `artifacts/`，同任务旁保存 `submission.zip`。原始任务产物不移动、不覆盖。清单记录原始需求、有序修改、实际交付、输入摘要、工具计划、源码摘要、耗时、模型调用及执行记录；不会主动复制真实config、密钥、参考答案或原始输入影像。对话正文和模型说明属于用户私有资料，仍需自行保管。

封存后使用收据中的清单SHA256检查全部文件。重复交卷只验证并返回原收据；不覆盖已有答卷。清单、栅格或ZIP改变时拒绝相应核验/下载。哈希收据需要另行保管，它不是数字签名，也不证明用户从未伪造整份答卷。失败、缺产物、缺答案、网格不一致和无受支持输出均明确保留，不编造分数。

网页评分报告单独保存到 `exports/assessments/`，不放进冻结答卷。清单在评分前后再次核验；评分函数没有Session参数，不写回会话，也不调用任何角色。网页交卷列表仅保留在本次服务内，重启后使用磁盘答卷和原收据做独立CLI评分。以下命令中的任务目录和64位SHA256必须替换为实际值，输出文件须为新文件：

```powershell
python -m benchmarks.assessment --submission 'results/实际任务目录/submission' --sha256 '交卷收据中的64位SHA256' --output 'exports/assessments/manual_01.json'
```

当前自动像元评分仅支持冻结清单中可唯一配对的水体案例。其他任务仍可交卷、保留成败与产物，但先标为不可自动评分；不能把完成率、F1或一次成功当作通用遥感能力总分。需求完成程度、方法适用性、解释准确性保留独立评审项。

## 干净运行包与严格隔离的边界

可准备只含运行代码、指定影像和必要元数据的干净包。例如使用一个不存在的新目录：

```powershell
python -m benchmarks.prepare --input 'benchmark_suite_20261025/water_05/image.tif' --destination 'exports/blind_runtime_manual_01'
```

它不复制benchmarks、答案配置、旧报告、旧结果、经验记忆、测试、文档、Git历史或真实API配置；元数据只保留波段、传感器、编码、单位、日期等允许的事实字段。影像像元和网格保持不变，元数据JSON经过筛选，不能声称原始元数据字节完全相同。使用原 `environment.yml` 建环境，安全配置相同模型/API，再从包根目录运行 `python main.py`，走同一个GUI/CLI。包内可以交卷，评分按钮禁用，将答卷带回独立评分端即可。

**当前完成的是应用路径分离和可转移的干净运行包，本机验证没有启用操作系统级权限隔离。** 相同Windows账户中的另一个目录或进程仍可能访问原答案；执行任意生成代码的现有Executor也不是权限沙箱。严格闭卷测试需将包放在无法挂载、读取原答案与评分端资料的独立机器、虚拟机或受限容器中运行。仅提示词或目录分开不能冒充严格隔离。

本机检测到Docker客户端并尝试启动Docker Desktop，但引擎未就绪，状态查询未及时返回；本批未安装容器环境或更改账户权限，系统级隔离未验证。收据和报告目前如实标记 `application_separation_only`，不能据此宣称严格沙箱验收通过。公开旧样本也可能已被开发或模型接触；本批只作流程回归，不宣称首次盲测或跨数据集泛化。
