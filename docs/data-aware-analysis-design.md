# 数据感知需求确认与结果核验

## 已确认问题

- Manager 未获得已有扫描元数据；Scientist 只得到文件路径，却被提示已提供波段元数据。
- 用户原文与修改意见已保留，但实际波段选择、ROI 与行政范围、系统限制仍可能被混为事实。
- Supervisor 在 Executor RESULT 检查前提前返回，实际没有核验本次产物。
- 结果文件存在或程序正常退出不能证明地物语义正确；最终报告还可能与统计表矛盾。

## 本次实施

1. 使用无需 LLM 的只读本地预检：读取 data/ 栅格元数据和有界降采样概况，保存 Session 快照；文件未变时复用，变动时刷新。批准时再次核对文件签名；等待批准期间有变化则重新生成确认摘要，GUI/CLI 不启动旧计划。采样不等同全量精确统计，全零像元不擅自声明 NoData，逐波段数值范围遵守各自掩膜。文件名中的日期、传感器、行政区域只作线索。
2. Manager 初次确认及修订前读取快照，Manager、Scientist、Engineer 使用同一份元数据。保持原始需求与修改顺序，区分事实、用户要求、系统限制、技术假设。确认区域口径与全部/部分波段，禁止无证据承诺精度或完整行政区覆盖。
3. Scientist/Engineer 明确记录波段使用与遗漏理由、特征工程与簇命名的分别约束；不靠兜底强行制造水体/植被/建筑。无证据的语义标签作为候选并标注待复核。
4. Executor 跟踪本次新增或覆盖的产物（含子目录）。Supervisor 确实执行本次产物核验，检查缺失、空文件、实际图像格式及完整解码、CSV 统计与分类栅格数量/面积/占比的一致性。有类别编号时逐编号核对，缺失时只确认数量分布并提示未核实名称对应。子目录同名表不合并；面积容差遵守 CSV 声明的小数精度。缺失和矛盾阻止成功交付；语义未验证标为待复核。
5. Manager 报告显式获取原需求、数据快照和机器核验事实；对直接可定位的“类别占比最高”句式检查与统计表的矛盾，发现时用核验后的确定性说明替代有冲突的模型总结。这不是任意自然语言结论的完整语义审查器。界面区分完成与结果待复核。

6. Manager 每次以完整原文、有序修订和当前数据构建提示，不再重复发送之前的累积数据快照；底层会话历史仍保留。数据预检快照记录在执行追踪中，便于导出审查。

## 范围与限制

不恢复结构化任务单，不更换框架，不变更一键托管入口与交互。不自动认定 TIFF 就是完整行政区，不从文件名认定产品级别。机器核验是数值/产物一致性检查，不能证明类别语义精度；没有独立样本时如实呈现待复核结果。历史结果保留，本次不会重新执行历史模型代码或产生付费 API 请求。

## 验证

使用临时小栅格和 CSV 的离线测试覆盖预检数据、缓存刷新、三角色共享、需求多轮修订、失败读取、本次产物追踪、统计错误、旧文件干扰和报告矛盾；最后用真实 TIFF 只读核验新快照并审计 20261021_191020 的六个现有产物。

独立只读代码审查发现的批准时数据过期、子目录同名 CSV 合并、中文格式名边界、截断 JPEG 和逐波段 NoData 问题均已复现后修复。真实历史结果的数值一致，但缺少编号对应与独立语义/行政区验证证据，应标为待复核；历史产物未重写。
