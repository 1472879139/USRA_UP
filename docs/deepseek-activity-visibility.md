# DeepSeek调用状态可见性修复（FIX-024）

## 已确认的问题与范围

用户反馈试用时未看到标志。只读核对发现7863已经返回FIX-023的新HTML和llm_activity字段，因此没有证据将问题归因于服务未重启或浏览器缓存。最近一轮运行有7次模型请求、10次工具调用（包括一次被拒绝的finish_task）；部分请求在约两秒内返回。

已复现的缺口：旧版只显示在途状态，两秒一次快照可能错过短请求；结束后又恢复“未调用”，不保留任何本轮调用痕迹。小标志位于标题内，也不够醒目。这些足以影响可见性，但不能据此断言已观察到用户原浏览器当时的具体显示原因。

本批延续codex/deepseek-tool-agent同一任务分支，保留已有改动。未改变模型配置、调用预算、提示词、遥感算法、真实输入及原任务产物；未调用真实付费API或GPU，未触发新的分析任务。

## 现在怎么显示

- 对话标题下面使用独立整行状态条；顶部目录扫描、右侧分析管线和对话过程保持原位置。
- 请求实际在途时：蓝色“DeepSeek正在调用”，附阶段、本轮第几次请求、等待或接收响应秒数。
- 请求返回或报错后：撤下转圈，保留“DeepSeek本轮已调用 N 次”。执行工具期间也显示累计次数，不能把GPU计算冒充为模型等待。
- 任务结束和刷新页面后：继续读取本会话计数；新建会话归零为“DeepSeek待命”。进程重启不回填旧会话计数。
- 轮询改为500毫秒；仍只保留一个计时器、单个在途轮询，沿用游标与会话代次保护。它仅增加本机状态读取频率，不增加模型调用。
- 连接失败：显示“DeepSeek状态待确认”，恢复后按实际快照更新。不人为延长忙碌动画。

## 共享字段与文件

保留active、agent、request_count、elapsed_seconds四个原字段；Session快照、导出及/api/updates.llm_activity同步新增：

| 字段 | 类型与默认值 | 含义 |
|---|---|---|
| total_requests | int，0 | 本会话已开始的API调用尝试数，含仍在进行和最终报错的请求 |
| finished_requests | int，0 | 已经正常返回或抛错结束的请求数，重复结束不会重复累计 |

这两个计数不是成功次数、服务商实际接收次数、费用或计费凭据；停止会话仍不能保证服务商已收到的请求被撤销。短于500毫秒的请求仍可能看不到转圈，但结束后的累计数不会因此消失。旧后端缺少新字段时前端兼容显示待命或在途状态。

| 文件 | 从什么变成什么 |
|---|---|
| core/session.py | 仅保存正在进行的请求 → 同时保留本会话开始/结束累计数，结束操作幂等 |
| gui/app.py | 空会话仅返回原四字段 → 新增计数默认0，与Session同步 |
| gui/templates/index.html | 标题小标志、两秒轮询、完成清空 → 整行状态条、500毫秒轮询、完成保留计数 |
| tests/test_llm_activity.py | 9项生命周期回归 → 13项，补短请求、跨会话、重复结束和空会话；阻塞测试经真实Flask路由读取 |
| tests/test_gui_polling.js | 30项 → 33项，覆盖短请求留痕、结束/刷新保留及新会话清零，并检查轮询间隔 |
| README.md、docs/fixes/README.md、docs/fixes/index.html | 当前说明和目录链接更新至本批；旧记录保持原快照 |
