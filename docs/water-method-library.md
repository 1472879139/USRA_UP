## 两种方法和无答案选路

原 `mndwi_zero / mndwi-zero-v1` 继续调用未改动的 `tools/water_tool.py`，使用MNDWI>0。新增 `mndwi_otsu / mndwi-otsu-v1` 从有效输入指数的256箱直方图计算阈值，再按指数大于阈值生成候选。其依据是最大化两组间方差，参见[scikit-image官方阈值说明](https://scikit-image.org/docs/stable/auto_examples/applications/plot_thresholding_guide.html)。本批以现有NumPy实现运算，没有安装scikit-image或新增环境依赖，也没有复制其源码。

两者统一提供掩膜、指数、预览、统计与方法JSON，处理实际波段描述、scale/offset、分母为零及NoData；不裁剪、不重采样、不按标签调阈值。0是非水候选，1是水体候选，255是无效/未确认，评分时仍按保守规则惩罚缺测。

`water-router-v1`候选规则仅使用输入像元：有效样本至少1024，指数位于[-1,1]且非近似常量，两组间方差占比至少0.75，较小组占比至少1%，交错抽样计算的阈值最大差不超过0.05。满足时尝试分布阈值，否则保留零阈值基线。**这些是工程适用性启发式，不是识别准确率或置信概率。** 回退到基线也不证明结果可靠；两组分布可能都是不同非水地物。water_01、03已有反例说明可分性不能保证语义改善。

普通需求、输入格式和最大8幅/每幅400万像元的约束沿用既有契约。用户指定其他方法、区域、矢量、水深、水质等需求继续原有规划，不被新规则覆盖。候选规则当前不作为默认发布；比较程序明确指定候选策略，正常调用默认由发布开关控制。

## 运行可重复实验

已生成本机可读报告：`exports/water_methods_comparison_20261026/comparison.html`，完整JSON、日志、运行包、40份答卷与收据均在同一目录。40次包括：十幅×三种策略×首种说法30次，以及十幅候选选路×第二种说法10次。全部处理和封存结束后才统一评分；失败或不可评分不删掉再算成功率。

重复实验可在项目环境中运行以下命令，输出必须是不存在的新目录。不会调用真实模型，也不改变普通聊天状态：

```powershell
python -m benchmarks.compare --case water_05 --case water_06 --output exports/water_methods_manual_01
```

这个CLI每幅各跑原方法、分布阈值、候选选路一次，生成comparison.json和comparison.html。角色使用真实代码，Manager回复模拟，Scientist/Engineer锁定工具；候选选路通过实验策略显式指定，不能冒充当前默认策略。真实DeepSeek联调未执行。

正常项目启动方式不变，重启后可在 `/benchmarks`运行water_07～10的固定基线，或在聊天输入“帮我圈出water_07中的水面，看看占多大面积”，结束后到 `/assessment`交卷评分。默认方法保持原样；不需要为看实验成绩反复运行water_05的普通对话。聊天仍沿用原API，用户手动执行可能产生服务商费用。
