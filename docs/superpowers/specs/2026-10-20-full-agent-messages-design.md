# 智能体消息全文与折叠设计

## 目标与范围

所有智能体消息在服务端、界面更新事件和会话导出中保留完整原文。聊天面板中较长的智能体消息默认折叠，并可逐条点击“展开全文”或“收起”；短消息直接显示，不提供多余按钮。不改动 Agent 工作链、模型请求、提示词或其他面板的交互。

## 根因与现状

`gui/app.py` 的 `_process_updates` 对除 Scientist 外的消息执行 `msg.content[:2000]`，截短后的文本进入界面事件、聊天历史和原始导出历史。`gui/templates/index.html` 的聊天气泡本身没有长度截断；只做前端展开无法恢复已被服务端删除的部分。先修复数据源，再做界面折叠。

## 数据流

`Message.content` 全文进入 `_chat_history`、`_raw_history` 和可重放的 UI 事件。已有的 `GET /api/updates?since=N` 协议保持不变；新旧页面按事件原文渲染。导出使用 `_raw_history`，因此新收到的消息均可导出全文。此设计不恢复此前已截短的旧消息，也不增加跨 Flask 进程的持久化。

## 展示与交互

只有智能体回复（包括 Supervisor）参与自动折叠。浏览器始终接收并安全转义完整文本，绝不再按字符切断；折叠仅限制气泡内容的可见高度。内容实际渲染高度超过约 240px 时，默认折叠并在气泡下方显示“展开全文”按钮；点击后取消高度限制并把按钮改为“收起”，再次点击恢复折叠。高度未超限时不显示按钮。每条消息独立控制；展开后容器依旧可滚动，代码等宽内容允许横向滚动。按钮应支持键盘操作，并暴露 `aria-expanded` 状态。

刷新页面后重放消息时，仍按同一规则创建折叠状态；不保存每条消息的展开选择。用户消息、系统通知和错误消息保持现有表现。服务器在内存中保留当前会话的全文，与已有事件重放设计一致。

## 错误与验证

消息缺失或为空时按现有逻辑显示，不生成折叠控件。前端使用现有转义流程，按钮不会将原文当作 HTML 插入。离线测试覆盖：超过 2000 字符的 Manager/Engineer 回复在事件、聊天历史和原始历史中全文一致；短消息无按钮；长消息默认折叠、点击展开再收起；重放后的长消息仍可切换。运行完整 Python 与 Node 回归测试，不调用付费模型。
