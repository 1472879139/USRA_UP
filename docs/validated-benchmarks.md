# 第一批：可重复的验收基础

本文保留FIX-008阶段范围。后续FIX-009已把固定水体工具接入普通对话并增加逐幅独立评价；当前使用方式和边界见[对话水体工具接入说明](validated-water-agent.md)，下文“下一批/尚未接入聊天”描述是第一批当时的状态。

本批基于 `2115157`，本地任务分支为 `codex/validated-water-benchmark`。新增独立的固定工具验收入口，不改变 DeepSeek API、角色提示词、普通聊天的规划执行链、CLI 或通用结果卡。这里验证“工具能否稳定执行、评分是否可信”，尚未验证自然语言 Agent 的任务规划、工具选择与自动纠错能力。

## 如何启动和测试

已有服务先在原终端按 `Ctrl+C`，然后在项目根目录重新启动。不需要重新安装环境：

```powershell
Set-Location 'C:\Users\17995\Desktop\USRA_UP'
cmd /d /c 'call "D:\Anaconda3\Scripts\activate.bat" ursa-up && python main.py'
```

打开 `http://127.0.0.1:7860/benchmarks`，或在主页顶部点击“验收测试”。选 `water_01` 或 `water_02`，点击“运行固定水体基线并独立评分”。这里不需要提示词、专业参数或付费模型请求。

页面首先显示通俗解释、图与三个指标；专业方法和完整 JSON 默认折叠。每次运行单独生成 `results/task_.../`，下载入口只允许本服务这次成功登记的固定文件。服务重启后，旧文件仍在本地结果目录，但旧下载链接需要重新运行后生成。

普通聊天仍可选择对应影像，并说：

> 帮我提取这幅影像中的水体，给我分布图和水体占比。

**聊天结果尚未自动接入本页评分**，因此它不一定采用本页固定方法，也不能直接套用本页成绩。当前按钮测试不需要提交这句话。下一批才把工具契约、工具选择、产物回传及相同评分协议接到 Agent 中，单独评价这条完整链路。

## 本机数据与可迁移配置

`benchmarks/cases.json` 冻结九个已有公开小案例的输入、元数据、参考答案、额外对照文件的相对路径和 SHA256。真实影像、标签和作者结果不进入 Git。

**注意：现有答案在项目外的测试包内，复制 `data/` 不会同时复制答案。** 本机已经生成被 Git 忽略的 `benchmark.local.json`，指向已有资料；源码只提供 `benchmark.example.json`。换电脑时单独复制：

| 材料 | 放置与配置 |
|---|---|
| `data/benchmark_suite_20261022/` | 保持项目内相对路径不变 |
| 测试包内的 `answers/` | 独立保存到自己选择的位置；`reference_root` 指向此目录 |
| 测试包内的 `others/` | 继续核对去云作者输出时复制；`comparison_root` 指向包含 `others/` 的测试包目录 |
| `benchmark.local.json` | 新电脑修改为当地实际路径；不要沿用旧盘符；不上传 Git |

可使用如下配置（路径仅为示例，不会自动下载或生成答案）：

```json
{
  "reference_root": "exports/evaluation_private/answers",
  "comparison_root": "exports/evaluation_private"
}
```

示例采用被Git忽略的 `exports/` 本地资料目录；也可把真实答案继续存放在项目外。没有配置、文件缺失或哈希改变时，页面说明具体原因，并禁止运行相应固定验收，不拿旧文件补本次结果。

去云、七类分割、变化检测、地表温度当前只核对材料完整性，页面明确显示“尚未接入工具和自动评分”。没有把这些方向伪装成已经完成。

## 方法、评分与避免虚高

固定水体基线版本为 `mndwi-zero-v1`，采用 `(Green-SWIR1)/(Green+SWIR1) > 0`。Sentinel-2 对应 B3/B11，依据栅格实际波段描述映射，支持 B03 与 B3；不会把 B11 当作第11波段。先转浮点并应用 TIFF scale/offset，处理掩膜、非有限值与分母零。冻结 ESWD 输入的公共 DN/10000 比例在比值中抵消。

指数依据可参见 [Sentinel Hub 水体指数示例](https://custom-scripts.sentinel-hub.com/custom-scripts/sentinel-2/simple_water_bodies_mapping-swbm/)。本工具只采用固定单指数基线，**没有复现该示例的多指数组合、阈值校准或云过滤**。数据来源为 [Xin Luo 发布的 ESWD](https://zenodo.org/records/5205674)，不是本项目制作的人工标签。

- 工具只接收输入路径及执行器提供的 `URSA_RESULTS_DIR`，不接收参考答案。写出预测后，独立评分器才读取答案。本批没有为任意生成代码构建操作系统权限沙箱，不能据此声称整个 Agent 永远无法访问答案。
- 栅格编码固定为 `0=非水候选、1=水体候选、255=无效`。阈值严格 `> 0`，没有按答案调参或后处理。最多400万像元，当前只面向小型验收案例；大场景分块尚未接入。
- 预测与答案尺寸、CRS、仿射变换必须一致，不自动重采样来凑分。标签已冻结为完整0/1编码，**0虽然被文件写成NoData，仍按有效背景统计**；该规则仅适用于清单中核验过的水体标签，不能推广到未知数据。
- 预测255不能丢弃：报告覆盖率，将缺测水体计入FN、缺测背景计入FP，给出保守指标并标记 `incomplete`。这是一种明确的缺测惩罚约定，不是假称模型预测了那些类别。未知标签或类别直接拒绝评分。
- 全背景且没有水体预测时，水体 Precision、Recall、F1、IoU 为 `null`（无法计算），不宣称水体检测100分。
- 报告 TP/FP/FN/TN、Precision、Recall、F1、IoU、总准确率。通俗卡主要展示前两项和F1，避免背景占比高造成总准确率误导。没有统一的80分合格线。
- 面积仅在投影坐标单位为米时，按像元仿射变换的行列式计算平面候选面积；不满足条件时为 `null`，不会用0冒充未知面积。占比分母为有效预测像元，另报告总像元与覆盖率。

输出包括候选分类栅格、指数栅格、输入与候选图、人工答案与误差图、统计表、方法说明和含文件哈希的验收报告。没有云、阴影与积雪过滤，所以它是水体候选方法，不能直接作为专业调查成果。

## 接口与兼容

新增 `GET /benchmarks`、`GET /api/benchmarks`、`POST /api/benchmarks/run`（JSON `case_id`）与 `GET /api/benchmarks/artifact/<run_id>/<name>`。页面消费独立 `report`，不改 `Message`、`Session` 序列化、已有轮询和 `result_delivery` 字段。验收使用独立Session仅分配任务目录，不替换当前聊天Session。

控制器新增内部布尔标记 `_benchmark_running`，默认缺省为false；验收路由在 `_ui_lock` 内读写，普通分析与新建对话在相同锁内读取，阻止互相重入。已有分析工作线程还活着时也不能启动验收。失败时 `finally` 释放忙碌标记，不把失败产物登记成成功下载。

本批不新增依赖，不改环境或真实配置。自动测试仅用临时合成影像与模拟控制器；完整检查命令见 [CONTRIBUTING](../CONTRIBUTING.md)。图文记录见 [FIX-008](fixes/2026-10-25-008-validated-water-benchmark.html)。当前为本地修改；本批未提交、未推送、未创建PR，审批与合并未执行。
