# FIX-014：远程Prithvi工具与无答案分歧检查

本批把已经独立试运行的Prithvi水体模型变成可重复调用的固定工具。用户选中符合条件的影像，输入“帮我圈出这张影像里的水体，告诉我大概占多少”，代码侧锁定调用，生成候选图、指数对照、分歧图及通俗说明。

这是工具调用与交付升级，没有更换模型权重、训练或按已知样本调阈值，不宣称识别精度提升。

## 输入范围

仅支持已经核对过的Sentinel-2 L1C影像：512×512、13个有明确描述的波段、原始DN/10000编码及真实坐标系。Blue、Green、Red、窄近红外B8A、SWIR1、SWIR2对应文件第2、3、4、9、12、13个波段。B8不替代B8A。

每个输入目录必须有可靠的 `metadata.json`，格式见[来源声明示例](../deploy/prithvi_gpu/input-metadata.example.json)。该文件是显式来源声明，不是对任意文件的来源认证。不能把L2A、普通RGB或任意六波段影像贴上标签后冒充匹配输入。大影像分块、其他传感器和其他任务本轮未支持。

指定面积、矢量、变化检测、裁剪、阈值或不同输出格式等需求，不会被本工具悄悄替换为默认水体候选任务。全无效输入在推理前拒绝；同一任务其余匹配影像可以继续，拒绝记录保留。全部无效时不生成结果。

## 运行结构

1. Manager依据本地输入事实说明适用条件，保留原始需求和有序修订。匹配固定工具时，确认说明直接来自实际能力；其他需求仍使用原DeepSeek规划路径，API配置保持原样。
2. Scientist仅对满足契约的普通水体任务建立 `remote_tool_plan`；未启用时保留原流程。
3. Engineer输出固定包装代码，不让模型改写Prithvi预处理、参数、地址或阈值。
4. Executor调用本机127.0.0.1的SSH转发地址，发送本次TIFF；GPU服务常驻加载权重，顺序处理请求。
5. 本机核对请求ID、输入哈希、模型版本、返回包成员、栅格网格、类别、有效区及本地重算指数。失败明确停止，不用旧结果、不静默退回其他方法。
6. Supervisor再次读取本任务原始返回包，独立重算指数、统计和分歧；不重新请求GPU、不读取人工答案。
7. 最终普通说明直接来自确定性核验事实；专业记录可展开。模型自评不参与准确性判断。

`remote_tool_plan`为Session新增字典字段，默认空字典；Scientist生产、Engineer/Executor/Supervisor消费，`Session.to_dict()`额外导出同名字段。原Message类型和已有字段不变。固定交接使用新增元数据键 `remote_tool_request`，不把用户原文变成工具控制指令。

## 结果如何解释

默认主结果是事先指定的Prithvi候选分类，另附固定MNDWI>0的独立对照。没有依据本次答案挑选赢家，也没有将两者并集或交集冒充更好的分类。

- 蓝色：两种方法都标为水体。
- 紫色：只有模型标为水体。
- 橙色：只有指数标为水体。
- 灰色：输入无效区域。

紫、橙表示方法分歧，不表示已知误报或漏检。分歧比例以两者候选水体并集为分母，避免大量背景让一致率看起来很高。双方都没标水体时不编造100%一致水体得分，而是说明“都未标出，仍不能证明没有水体”。

文件检查通过、方法一致或两种结果有分歧，都不能替代独立准确性评价。正常运行路径不接收标签参数、不查找参考答案；有标注时应在交卷后使用独立评分器。

本轮为单时相水体候选，不能区分新增洪水与永久水，也不推算水深、损失或危险等级。
