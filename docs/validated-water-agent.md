# FIX-009：把水体固定工具接入普通对话

这是同一水体验收与接入任务的第二批本地修改，继续使用 `codex/validated-water-benchmark`。保留FIX-008未提交改动及其历史HTML。本轮未提交、未推送、未创建PR，审批和合并均未执行；没有更新共享main。

## 本次解决的问题

2026-10-25的用户测试完成了文件生成，但第一幅参考水体仅找回约13%。普通对话自行采用双指数交集与碎斑过滤，把大量真实水体留成了“待核实”；它没有调用验收页的固定方法。另有输入简称未绑定、water_mask未进入分类核验、简明卡只取首张表等问题。

本批将固定方法接入既有角色链，并补齐独立评价与逐幅交付。没有按两幅图的人工答案修改阈值，也没有训练或下载新模型。

点击“自动分析”可走托管流程；点击发送则先查看Manager确认，再点击“确认开始”。也可以在上方选择这两个目录中的 `image.tif`，只说“帮我找出这些图里的水体，告诉我有多少”。

结果逐幅显示水面候选面积、可分析区域占比、图像及评价；专业说明仍在结果下方按需展开。右侧管线、顶部可折叠目录扫描和对话区分析过程保留。现有旧会话不会自动重跑，新任务仍按 `results/task_.../` 隔离。

真实网页中的Manager仍使用既有DeepSeek配置。本轮验证将模型响应全部模拟，未发起收费联调。

## 方法选择与输入边界

- 原始需求、有序修订、确认语义继续保留；`approve`仍是控制指令。
- 支持不重名的目录简称，例如 `water_01和water_02`；重名不能静默选择，指向不存在文件的路径不能替换成同目录其他影像。明确的界面文件选择保持原有优先级。
- 普通水体需求优先使用 `water_mndwi_zero / mndwi-zero-v1`。要求锁定的输入可读、每幅最多400万像元、本地 `metadata.json` 明确声明Sentinel-2六波段和反射率DN/10000编码，实际波段描述与声明一致。最多8幅串行处理。
- 这些是工具适用条件，不能只看到B11就猜它是短波红外。输入和元数据在规划时计算哈希，执行前后再次核对；元数据变更也进入数据预检签名，防止沿用旧批准。
- 用户指定双指数、其他阈值、模型、区域裁剪或额外交付限制时，不静默覆盖要求，继续既有规划路径；这些自定义方案尚未自动接入固定工具评价协议。
- 固定工具是候选提取方法，未使用云、阴影和积雪掩膜，没有专业语义精度保证。适用条件不足时不能宣称工具已接入成功或模型已经验证。

## 角色与失败处理

| 环节 | 本轮行为 | 失败处理 |
|---|---|---|
| Manager | 看同一份预检和输入约定；有可用固定工具时说明该方案 | 数据变化需重新确认；缺少明确输入时要求选择 |
| Scientist | 对符合契约的普通水体需求生成固定工具计划 | 不猜传感器；明确其他要求仍交原规划路径 |
| Engineer | 核对计划与Session一致，生成固定调用包装代码 | 不接受篡改计划，不调用模型重写已锁定工具 |
| Executor | 沿用实际子进程与URSA_RESULTS_DIR；补充源码模块路径 | 工具输入/版本或执行失败明确终止并要求检查条件 |
| Supervisor | 分类栅格、CSV及工具清单交叉核验，之后才独立读答案 | 文件、数值或绑定不一致视为核验失败 |
| Manager/前端 | 逐幅引用核验与独立评价事实 | 无答案不编造精度；未确认区域不说成完整识别 |

一般动态生成代码仍保留原有最多5次执行（含首次）的工程修复循环。**固定工具失败时不让模型改写受保护的算法或检查规则来绕过问题**，也不对同一确定性错误重复付费尝试。科学精度不足时本批会明确展示漏检和误报，尚未实现多算法自动重规划与质量择优循环。

这是已验证工具接入的第一条路径，不等于任意遥感问题已经自动解决；其他方向继续按独立方法、数据契约与指标接入。

## 独立评价与防止虚高

生成阶段仅读取已锁定影像和波段说明，不读取参考答案。工具执行完成后，Supervisor用输入文件SHA256匹配冻结案例；匹配唯一、答案哈希正确且网格一致时，才读取独立答案评分。文件名相似不足以配对，没有答案或答案改变时不显示精度数字。

人工答案仍单独保存，本机 `benchmark.local.json` 的配置沿用FIX-008；跨电脑需要另带 `answers/`，详见[资料迁移说明](migrate-to-another-computer.md)。不向预测工具提供答案路径或标签内容。当前执行器不是操作系统级权限沙箱，不能声称任意生成代码永远无法访问答案。

预测255表示无效/未确认，不能删除后提高成绩。专业指标沿用缺测按错误计入FP/FN的保守约定，并报告覆盖率。通俗卡同时显示“已标出候选的正确比例”和“全部参考水体的找回比例”；后者包含未确认水体。二者含义不同，不能把保守惩罚直接说成已经预测出的误报。

原通用核验器现在识别单波段整数 `*_mask.tif`。CSV新增可选列“分类栅格”，可明确绑定同一任务中的栅格；类别表明确列出NoData编号时，该类一同核对。禁止借另一幅像元数量相似的图通过检查。数值一致仍不等于类别正确。

## 本轮真实输入离线重放

使用原始两幅公开影像、实际GUI编排、实际Executor子进程和独立评分；Manager响应模拟，Scientist/Engineer走固定工具契约，真实API请求为0。

| 案例 | 之前找回率 | 本轮找回率 | 之前保守F1 | 本轮F1 | 本轮标出面积 |
|---|---:|---:|---:|---:|---:|
| water_01 | 12.99% | 88.99% | 20.93% | 88.96% | 4.3830平方公里 |
| water_02 | 97.02% | 99.79% | 97.96% | 96.58% | 12.6241平方公里 |

参考标签水面分别为4.3796和11.8383平方公里。本轮标出候选的正确比例分别为88.92%和93.58%。第一幅改善明显；第二幅找回更多水面，同时误报更多、F1略降。总面积接近也可能由误报和漏检抵消，不能仅凭面积判断边界准确。

两例都是已看过的回归样本。这些数值证明本轮工具接入复现了固定方法，不代表新地区或所有遥感任务的精度。没有用答案为两幅图分别调参选择方法。

## 接口变化

| 字段 | 类型/默认值 | 生产者 → 消费者 |
|---|---|---|
| `task_contract.input_ambiguities` | 字符串列表，默认空 | 输入绑定 → 适用条件检查、角色上下文与专业详情 |

状态机枚举、原消息类型、轮询游标和既有API路由不变。工具从验收模块迁到 `tools/water_tool.py`，`benchmarks/water.py` 保留兼容导入；验收页和对话调用同一实现。
