# TerraMind Small地物类别生成与独立评价

本阶段在Small基础编码器验收之后，增加官方LULC生成解码路径。默认固定五个官方S2L2A示例，只做探索性复现。真实GPU分类推理和独立评分尚未执行；当前不能声称分类准确或已经接入一句话Agent。

## 从什么到什么

- 原入口 `deploy.py` 保持原有特征提取验收功能。
- 新入口 `landcover.py`：原始十二波段DN → Small完整生成模型 → 官方LULC解码器 → 候选类别GeoTIFF、中文类别占比、RGB与分类预览、HTML、封存ZIP。
- 新打包器 `build_landcover.py`：仅打包推理代码、输入协议和五个输入；显式配置模块搜索路径，独立子进程可导入依赖模块。
- 新评分器 `evaluate_landcover.py`：在Windows取回封存包后，读取另存的参考图计算逐类IoU、F1、精确率、召回率、像素一致率和总体mIoU。它和参考图均不进入GPU包。

当前工具是Agent接入前的独立能力验收。提示词记录为“帮我识别这张影像中的主要地物，并给出一张分类图和各类占比。”；本工具固定执行这一任务，没有用语言模型解析任意需求，也没有调用DeepSeek。

复用已下载的Small权重：提交 `960f7549bfe9d7a08946860042f83badd604c779`，SHA256 `755e9cce9483fd61334ef66c79f805406db5151a8b44a685c8fbbe023c684701`。

新增官方 [LULC Tokenizer](https://huggingface.co/ibm-esa-geospatial/TerraMind-1.0-Tokenizer-LULC)：
提交 `af6b7c73a36994e25df156e793901969efe88ec9`；文件735,693,536字节；
SHA256 `0e318c41490b472897b328256227c049aba8c1671a88c1ef3a1fa5026b3e0fd3`。

复用原Python3.11、PyTorch2.10.0+cu128、TerraTorch1.2.11、TorchGeo0.8.1、NumPy2.2.6和Rasterio1.4.4。
缺失时仅补装 `diffusers==0.30.0`，固定官方wheel哈希、`--no-deps`、随后 `pip check`；不升级Torch或GIS依赖。已有diffusers版本会保留，并在独立离线进程检查实际LULC解码与生成接口，预检通过才下载权重。预检失败会报告实际版本和原始错误，不自动降级。接口导入通过不等于完整推理已通过；后续仍严格核对全部权重并执行真实计算。首次运行要求至少2GiB空闲磁盘用于新增模型；不下载其他输出模态的解码器。

生成网络使用 `pretrained=False` 仅构建结构，随后手工核对并严格加载Small主模型和LULC tokenizer的全部所需参数。共享embedding别名也核对；缺失、形状不符、已有模型文件哈希不符均停止，不用随机参数补齐。生成阶段阻断新建网络连接。

使用float32、固定种子20261028加样本序号、解码步数1、top-p 0.8、温度1.0；启用确定性算法，关闭TF32。LULC使用VQ-VAE解码；传入的timesteps=10不是分类精度指标。使用官方预训练标准化，不把原始DN乘0.0001，不添加未经核对的offset。

## 类别和输入

TerraMind v1使用连续0～9编码，来自ESRI类别体系：

| 编码 | 类别 |
|---|---|
| 0 | 无类别 |
| 1 | 水体 |
| 2 | 树木 |
| 3 | 淹水植被 |
| 4 | 农作物 |
| 5 | 建成区 |
| 6 | 裸地 |
| 7 | 雪和冰 |
| 8 | 云 |
| 9 | 草灌覆盖 |

这不是ESA WorldCover的类别编码。输出255专门表示输入无效；模型预测0不能在评分时删去。解码器得分未经校准，不作为“准确率”或“可信百分比”。

五个输入来自IBM官方示例，固定公开仓库提交 `53d61da09213c2c3629931b6322f94cce617886a`：

`38D_378R_2_3`、`282D_485L_3_3`、`433D_629L_3_1`、`637U_59R_1_3`、`609U_541L_3_0`。

所有输入均十二波段、224×224、具有10米投影网格，原始DN、完整有效像元。每幅文件SHA固定在 `landcover-manifest.json`；预检不符会拒绝。当前不自动裁剪、填补或适配任意用户影像。

## 构建和服务器执行

在本任务仓库中构建；影像只放外部数据目录：

```powershell
python deploy/terramind_gpu/build_landcover.py --inputs "输入目录" --output "新执行包.pyz"
```

打包器按明确名单取文件，不遍历整个数据目录；不会把旁边的答案、评分器、配置或缓存打包。输出同名SHA256文件。执行包解压至服务器独立哈希目录；已有文件被修改则拒绝覆盖。

Windows保持原22022隧道，先SCP执行包，成功后SSH登录GPU：

```powershell
scp -P 22022 "本机执行包的完整路径.pyz" "yy@127.0.0.1:~/ursa-terramind-landcover-20261028-r2.pyz"
ssh -p 22022 yy@127.0.0.1
```

在Ubuntu执行：

```bash
bash ~/ursa-gpu-runtime/run-python.sh ~/ursa-terramind-landcover-20261028-r2.pyz
```

保留既有libstdc++启动包装器。默认先检查依赖、Small权重、输入，再补生成依赖和下载LULC解码器，随后通过独立离线子进程推理。可重跑原命令续下载；不会覆盖错误SHA的模型文件。已准备模型也可用相同执行包加 `--run` 直接离线运行；该路径同样检查实际接口。加 `--check-generation` 只执行离线导入预检，不安装、不下载，也不执行模型前向。

成功标志是“本轮封存：5/5完成”，但这只代表计算与产物核验通过，尚未代表分类效果好。

## 取回和独立评分

每次运行创建唯一目录，尊重执行器提供的 `URSA_RESULTS_DIR`，默认 `~/ursa-gpu-runtime/results/`。ZIP包含本次类别图、统计、预览、逐例状态、运行来源、耗时和本进程PyTorch峰值allocated显存、SHA清单。显存数不是GPU总占用；耗时不是整个Agent响应时间。

所有失败也封存；若不足5例完成，进程返回非零并提示取回诊断。根据终端打印的SCP命令在Windows下载ZIP，再执行：

```powershell
python deploy/terramind_gpu/evaluate_landcover.py --archive "本次结果.zip" --inputs "固定输入目录" --references "仅本机参考图目录" --package "本次执行包.pyz" --output "新评分输出目录"
```

评分器先验证封存清单、包哈希、输入哈希、模型哈希、固定参数、样本顺序、种子与网格，不能用旧任务或不同参数的结果充数。包内SHA清单用于检测传输或文件改动，不是远程执行真实性的加密证明。

计分规则预先固定：

- 只忽略原始输入/参考掩膜无效区域和参考类别0。
- 模型预测0或255均在有效参考区域计为未决策错误，不能通过缩小掩膜提高分数。
- 整例执行失败或预测产物损坏，按全图未决策计入总体；同时报告有效产物例数。
- mIoU在1～9类中按预测或参考出现的类别计算；缺席类别记不可计算，不编成满分。保留逐例、逐类、总体混淆矩阵。
- 参考标签不是连续0～9时拒绝评分，不猜测重编码。

## 证据边界与后续

[官方模型卡](https://huggingface.co/ibm-esa-geospatial/TerraMind-1.0-small#generations)明确生成的是模型想象的模态。此处称“候选类别”，并通过外部产品检验，不能默认等同于经过任务微调的语义分割头。

参考来自官方示例配对ESRI产品，本身不是独立人工真值，示例与预训练数据是否重叠也未排除。因此分数只说明探索性的产品一致性。查看输入和参考的格式、网格、哈希不等于做过性能评测；本阶段尚未读取参考像素用于评分或调参。

五例运行封存后按固定规则评分、诊断主要混淆，再决定补独立留出集和微调任务头。性能未证明前，保持独立测试入口，不自动接入生产Agent。
